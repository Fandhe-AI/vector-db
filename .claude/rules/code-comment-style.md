# コメント規約

## 目的

後続の読み手（Claude を含む）は渡された情報からしか判断できない。
コメントはクレート・モジュール視点での役割と、他クレート・他モジュールとの
文脈を埋め込み、ファイル単体で文脈が伝わる状態にする。

## 何を書くか

- このファイル・モジュール・関数の役割と責務境界（1〜2 行要約をドキュメンテーションコメントで）
- 呼び出し元・呼び出し先の文脈（「wire-server の接続ハンドラから呼ばれる」「engine の検索カーネルを呼んで結果セットを返す」等）
- 他クレートとの契約（engine ⇔ wire-server のインターフェース・エラー契約 `wire_code`・前提条件）
- spec のビヘイビア対応（該当する場合は TASK-nn・ビヘイビア ID を**ポインタ表記**で。spec 本文は転記しない）
- 非自明な前提・副作用・エラー処理の意図（特に fail-closed の判断・untrusted 入力の検証根拠）

## 何を書かないか

- コードを読めば分かる逐語説明（`i += 1;  // i をインクリメント` 等）
- 陳腐化しやすい実装詳細の重複（コードと 2 重に管理しない）
- `docs/spec`（private）の本文引用（[spec-confidentiality](./spec-confidentiality.md)）

## ドキュメンテーションコメントの形式

- Rust: クレート・モジュールの入口は `//!`、公開 API は `///` で 1〜2 行の役割要約を必ず付ける
- コメントは日本語で書く（[japanese-style](./japanese-style.md)）
- `unsafe` ブロックには理由と維持すべき不変条件を必ず明記する
