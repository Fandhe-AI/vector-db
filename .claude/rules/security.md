# セキュリティ規約

## 秘密情報の混入防止（P0）

- 実トークン・実 API キー・接続資格情報をコード・テスト・fixture・ドキュメントに書かない（例示はダミー値・パターン表記に限る）
- `.env` 等の資格情報ファイルをコミットしない
- hooks・settings.json にシークレットをハードコードしない

## private spec の漏えい防止（P0）

- [spec-confidentiality](./spec-confidentiality.md) に従う（本リポは public、`docs/spec` は private）

## テナント境界（P0）

- RLS 相当のテナント分離・認証・認可の検査を外す/緩める/バイパス経路を作らない
- fail-closed を維持する（fail-open にする変更は P0）
- エラー・ログ経由で他テナントのデータ・存在情報を漏らさない

## OWASP Top 10 観点（PR 作成前チェック）

| 観点 | 本リポでの具体例 |
| ---- | ---------------- |
| インジェクション | `USING PLAN(...)`・SQL 文字列組み立てへの未検証入力連結 |
| 認証の不備 | wire プロトコル認証フローの検証省略・タイミング差による情報漏えい |
| アクセス制御の不備 | テナント境界チェックの欠落パス |
| 不安全な設計 | fail-open なエラー経路・無制限リソース確保（DoS） |
| セキュリティ設定ミス | デフォルト認証無効・過剰なログ出力 |
| 脆弱な依存 | 未固定バージョン・メンテ停止クレート（[dependency-policy](./dependency-policy.md)） |

## 運用

- `git commit --no-verify` を使用しない（pre-commit フックを必ず通す）
- セキュリティ上の疑義を発見した場合は作業を中断してユーザーに警告する
